Backend — 6 missing features
Server and infrastructure gaps
🔑
Google OAuth + Apple OAuth login
The Sign In modal has Google and Apple buttons — they are UI only. No backend. Users cannot actually log in with Google. Need: passport + passport-google-oauth20 + passport-apple. The user_oauth table is already in the schema waiting for this.
critical
⚡
Socket.io — real-time WebSockets
The live reading rooms in community-hub.html are a visual only. The live reader counter is simulated with setInterval. The "writing now" badge on the author page is hardcoded. Socket.io turns all of these into real live connections — readers see each other typing, live reader counts update instantly, authors see followers joining their drafts.
critical
📤
File uploads — book covers + author photos
Authors can enter a cover_url in the publish book form — but they cannot upload an actual image. There is no POST /api/upload endpoint. Need: multer + AWS S3. The schema has cover_url fields on both books and author_profiles ready to store the URL.
critical
💸
Author payouts — Stripe Connect
Readers pay via Visa card and the platform collects the money. But authors never actually receive their 95% cut. Stripe Connect allows authors to link their own bank account so their share transfers automatically. The author_payouts table is in the schema — no code exists for it yet.
important
🔍
Full-text search index — search_index table unused
The schema has a search_index table with tsvector columns and GIN indexes for fast full-text search. The current GET /api/search uses ILIKE which is slow on large datasets. Replacing it with to_tsvector queries makes search instant across 4.2M books.
important
🧹
pg_cron — automatic database cleanup jobs
The live_readers table fills up with stale rows forever. The schema mentions pg_cron jobs to clean them every 10 minutes — these are not set up. Also needed: monthly patron payout summaries, expired token cleanup, and trending book score recalculation every hour.
important

Database (db.js) — 5 tables in schema but not in db.js
These tables exist in PostgreSQL but have no query functions yet
🔑
user_oauth table — no query functions
Stores Google/Apple/Twitter OAuth tokens. Needed when OAuth is built — db.userOauth.findOrCreate(), db.userOauth.link() etc. Currently this table is unused.
needed for OAuth
💰
author_payouts table — no query functions
Tracks monthly author earnings and Stripe Connect payout transfers. Needed when author payouts are built. db.authorPayouts.record(), db.authorPayouts.listByAuthor() etc.
needed for payouts
📖
club_books table — no query functions
Links books to reading clubs — the current book a club is reading. No db.clubs.setCurrentBook() or db.clubs.getCurrentBook() functions exist.
minor
💡
soul_responses table — no query functions
Stores each individual quiz answer for soul profile refinement over time. Currently the soul profile is computed once and saved — individual answers are not stored for future retraining.
minor
👥
chapter_followers table — no query functions
Tracks who is following an author's live chapter draft. The POST /api/chapters/:id/follow endpoint exists but writes to an in-memory Map rather than this table.
minor

later

No /api/docs page exists. Publishers, developers, and partner apps need a documented API to integrate. swagger-ui-express + swagger-jsdoc auto-generates this from comments in server.js.
