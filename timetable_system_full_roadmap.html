🛠 Best language & technology stack — with reasons

Backend language
JavaScript (Node.js) Recommended
You already know JS from your BIT coursework. The GA algorithm, REST API, and database queries all run in the same language — no context switching. Python is also valid (Flask/Django), but Node.js gives you one language across the whole stack.
Web framework
Express.js Recommended
Minimal, unopinionated, and the most-documented Node.js framework. Perfect for REST APIs. Alternative: Fastify (faster but less beginner resources).
Database
PostgreSQL Recommended
Relational constraints (lecturer ↔ course ↔ room ↔ timeslot) are a natural fit for SQL. PostgreSQL handles complex joins and constraint checking better than MySQL. Use Railway's free Postgres for hosting.
Frontend
HTML + Vanilla JS
No build tools, no framework overhead. You can open the file in any browser during development. Use CSS Grid for the weekly timetable layout. React is unnecessary complexity for this project scope.
Optimization algorithm
Genetic Algorithm (GA)
Directly supported by your proposal (Bensky & Saunders, 2025). Easier to implement and understand than Simulated Annealing. GA is the industry standard for university timetabling problems.
Hosting
Railway + Netlify
Railway hosts the Node.js backend + PostgreSQL database for free. Netlify hosts the HTML frontend for free. Both have simple GitHub integration. Zero server administration needed.

-- 1. Departments CREATE TABLE departments ( id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, college VARCHAR(100) ); -- 2. Rooms CREATE TABLE rooms ( id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, capacity INTEGER NOT NULL, type VARCHAR(20) CHECK (type IN ('lecture', 'lab', 'seminar')) NOT NULL ); -- 3. Time slots (e.g. Monday 08:00-10:00) CREATE TABLE time_slots ( id SERIAL PRIMARY KEY, day VARCHAR(10) CHECK (day IN ('Monday','Tuesday','Wednesday','Thursday','Friday','Saturday')), start_time TIME NOT NULL, end_time TIME NOT NULL ); -- 4. Lecturers CREATE TABLE lecturers ( id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, email VARCHAR(100) UNIQUE, department_id INTEGER REFERENCES departments(id) ON DELETE SET NULL, max_hours_per_day INTEGER DEFAULT 6 ); -- 5. Courses CREATE TABLE courses ( id SERIAL PRIMARY KEY, code VARCHAR(20) NOT NULL UNIQUE, name VARCHAR(150) NOT NULL, department_id INTEGER REFERENCES departments(id) ON DELETE SET NULL, credit_hours INTEGER NOT NULL, student_count INTEGER NOT NULL, requires_lab BOOLEAN DEFAULT false, year_group INTEGER CHECK (year_group BETWEEN 1 AND 4) ); -- 6. Who teaches what (many-to-many) CREATE TABLE course_lecturers ( id SERIAL PRIMARY KEY, course_id INTEGER REFERENCES courses(id) ON DELETE CASCADE, lecturer_id INTEGER REFERENCES lecturers(id) ON DELETE CASCADE, UNIQUE(course_id, lecturer_id) ); -- 7. Lecturer time preferences (soft constraints) CREATE TABLE lecturer_preferences ( id SERIAL PRIMARY KEY, lecturer_id INTEGER REFERENCES lecturers(id) ON DELETE CASCADE, time_slot_id INTEGER REFERENCES time_slots(id) ON DELETE CASCADE, preference_level INTEGER CHECK (preference_level BETWEEN 1 AND 5) DEFAULT 3 ); -- 8. Generated timetable entries (the algorithm output) CREATE TABLE timetable_entries ( id SERIAL PRIMARY KEY, semester VARCHAR(20) NOT NULL, course_id INTEGER REFERENCES courses(id), lecturer_id INTEGER REFERENCES lecturers(id), room_id INTEGER REFERENCES rooms(id), time_slot_id INTEGER REFERENCES time_slots(id), created_at TIMESTAMP DEFAULT NOW() ); -- 9. Users (admin authentication) CREATE TABLE users ( id SERIAL PRIMARY KEY, name VARCHAR(100) NOT NULL, email VARCHAR(100) UNIQUE NOT NULL, password_hash VARCHAR(255) NOT NULL, role VARCHAR(10) CHECK (role IN ('admin', 'viewer')) DEFAULT 'viewer' );
⚠ Run these tables in order — later tables reference earlier ones via foreign keys. If you get an error about a table not existing, you've run them out of order.

AlgorithmBuild the constraint validator — utils/validator.js
This function takes a complete proposed timetable and checks every hard and soft constraint. It returns a score — lower score means fewer violations. The GA uses this to decide which timetables are better. Build and test this in complete isolation before touching the GA.
5 hard constraint checks3 soft constraint checksReturns numeric score

// utils/validator.js // Input: assignments = [{course_id, lecturer_id, room_id, timeslot_id}] // Input: data = {courses, rooms, timeslots} (loaded from DB) // Output: {score, hardViolations, softViolations} function validate(assignments, data) { const hardViolations = []; const softViolations = []; // --- HARD CONSTRAINT 1: No lecturer double-booked --- const lecturerSlots = {}; for (const a of assignments) { const key = `${a.lecturer_id}-${a.timeslot_id}`; if (lecturerSlots[key]) { hardViolations.push(`Lecturer ${a.lecturer_id} is double-booked at slot ${a.timeslot_id}`); } lecturerSlots[key] = true; } // --- HARD CONSTRAINT 2: No room double-booked --- const roomSlots = {}; for (const a of assignments) { const key = `${a.room_id}-${a.timeslot_id}`; if (roomSlots[key]) { hardViolations.push(`Room ${a.room_id} is double-booked at slot ${a.timeslot_id}`); } roomSlots[key] = true; } // --- HARD CONSTRAINT 3: Room capacity --- for (const a of assignments) { const course = data.courses.find(c => c.id === a.course_id); const room = data.rooms.find(r => r.id === a.room_id); if (room && course && room.capacity < course.student_count) { hardViolations.push(`Room ${room.name} too small for ${course.code} (${course.student_count} students)`); } } // --- HARD CONSTRAINT 4: Lab courses need lab rooms --- for (const a of assignments) { const course = data.courses.find(c => c.id === a.course_id); const room = data.rooms.find(r => r.id === a.room_id); if (course?.requires_lab && room?.type !== 'lab') { hardViolations.push(`${course.code} requires a lab but is assigned to ${room?.type} room`); } } // --- HARD CONSTRAINT 5: Same year-group cannot clash --- const yearSlots = {}; for (const a of assignments) { const course = data.courses.find(c => c.id === a.course_id); if (!course) continue; const key = `${course.year_group}-${a.timeslot_id}`; if (yearSlots[key]) { hardViolations.push(`Year ${course.year_group} has two classes at slot ${a.timeslot_id}`); } yearSlots[key] = true; } // Score: hard violations are heavily penalized const score = hardViolations.length * 1000 + softViolations.length * 10; return { score, hardViolations, softViolations }; } module.exports = { validate };
  • Test it by hand: create a fake assignments array with a deliberate double-booking and check the output
  • The fitness score must decrease as the GA runs — if it doesn't, check this function first
AlgorithmImplement the Genetic Algorithm — utils/ga.js
The full GA engine: population initialization, fitness evaluation, tournament selection, single-point crossover, and mutation. This is the part that makes your system intelligent. Each "chromosome" is a complete timetable. The GA evolves 50 of them simultaneously over 500 generations.
Population: 50Generations: 500Mutation: 5%Tournament selection
▾ Click to see the full GA implementation
// utils/ga.js const { validate } = require('./validator'); const POP_SIZE = 50; const GENERATIONS = 500; const MUTATION_RATE = 0.05; // Create one random timetable (chromosome) // One gene per course: {course_id, lecturer_id, room_id, timeslot_id} function randomChromosome(data) { return data.courses.map(course => { const lecturer = randomFrom(data.courseLecturers[course.id] || data.lecturers); const room = randomFrom(data.rooms); const slot = randomFrom(data.timeslots); return { course_id: course.id, lecturer_id: lecturer.id, room_id: room.id, timeslot_id: slot.id }; }); } function randomFrom(arr) { return arr[Math.floor(Math.random() * arr.length)]; } // Tournament selection: pick the best of 3 random candidates function select(population, data) { let best = null; for (let i = 0; i < 3; i++) { const candidate = randomFrom(population); const { score } = validate(candidate, data); if (!best || score < best.score) best = { chromosome: candidate, score }; } return best.chromosome; } // Single-point crossover: swap halves of two parents function crossover(parentA, parentB) { const point = Math.floor(Math.random() * parentA.length); return [...parentA.slice(0, point), ...parentB.slice(point)]; } // Mutation: randomly reassign a gene with MUTATION_RATE probability function mutate(chromosome, data) { return chromosome.map(gene => { if (Math.random() < MUTATION_RATE) { return { ...gene, room_id: randomFrom(data.rooms).id, timeslot_id: randomFrom(data.timeslots).id }; } return gene; }); } // Main GA function — call with all data loaded from DB function generate(data) { let population = Array.from({ length: POP_SIZE }, () => randomChromosome(data)); let bestEver = null; let bestScore = Infinity; for (let gen = 0; gen < GENERATIONS; gen++) { // Evaluate all const scored = population.map(c => ({ chromosome: c, score: validate(c, data).score })); scored.sort((a, b) => a.score - b.score); if (scored[0].score < bestScore) { bestScore = scored[0].score; bestEver = scored[0].chromosome; console.log(`Gen ${gen}: best score = ${bestScore}`); } if (bestScore === 0) { console.log('Perfect timetable found!'); break; } // Create new generation: keep top 10 (elitism), fill rest with children const newPop = scored.slice(0, 10).map(s => s.chromosome); while (newPop.length < POP_SIZE) { const child = mutate(crossover(select(population, data), select(population, data)), data); newPop.push(child); } population = newPop; } return { bestChromosome: bestEver, bestScore }; } module.exports = { generate };
⚠ Test locally first: node utils/ga.js with mock data before connecting to the DB. Watch the score drop in the console log — it should decrease over generations. If the score stays the same, your mutation rate or selection is broken.

Railway backend deployment checklist

  • Push project to GitHub (make sure .env is in .gitignore — never commit secrets)
  • Create new Railway service → connect your GitHub repo
  • Add environment variables in Railway web UI: DATABASE_URL, JWT_SECRET, PORT=3000, NODE_ENV=production
  • Add a PostgreSQL database from Railway's "Add Plugin" — it auto-sets DATABASE_URL
  • Run schema SQL in Railway Postgres Console
  • Run seed scripts pointing to the production DATABASE_URL
  • Test the live API: https://your-app.up.railway.app/health

Netlify frontend deployment checklist

  • Update the API constant in all HTML files from localhost:3000 to your Railway URL
  • Put all HTML/CSS/JS files in a /public folder
